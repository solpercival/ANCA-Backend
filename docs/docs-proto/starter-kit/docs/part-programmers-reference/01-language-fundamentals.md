# Language Fundamentals

---

## Program Structure

A part program comprises a combination of:
- Blocks
- Subroutine definitions.

### Part Program Blocks

A block in a part program is equivalent to a statement in a language like Pascal or C. A block consists of:

- Block skip character (optional)
- Sequence number (optional)
- Block body
- Block delimiter/continuation

#### Block Skip Character
The block skip character and the sequence number are optional but may **not** be programmed together in one block.

The block skip character is `/`. If `/` is programmed at the beginning of a block, the rest of the block is ignored if the block skip signal is present from the PLC[^2]. If the block skip signal is not present, the block is executed as usual.

**Additional information:**
1. The block skip signal is normally linked to a front panel push button or to a control panel push button.
2. A block with a block skip character must not have a sequence number programmed with it.
3. The block skip signal is checked during program lookahead (see "What is Lookahead?" page 263).

#### Sequence Number
Sequence numbers are programmed by `N` followed by a positive number. Sequence numbers are optional and useful for later references.

**Additional information:**

1. Sequence numbers may be defined in any order and by arbitrary increments.
2. Programming a sequence number twice results in a syntax error.
3. Sequence numbers defined in the body of a part program are local to that part program.
4. Sequence numbers defined in a subroutine are local to that subroutine.
5. Sequence numbers are local to each level of nested control flow blocks in which they are defined.

#### Block Body

The block body is the actual statement part of the block, usually providing the information of the move to be executed or the task to be performed.  It consists of one or more of the words. A non-exhaustive list of words

- Preparatory word (G-code)	`G<n>` or mnemonic.
- Miscellaneous word (M-code)	`M<n>` or mnemonic.
- Feedrate word	`F`/`feedrate` or `vpv` and `vpl`.
- Spindle speed word (S-code)	`s`, `ss`, `sss`, `ssss` or `mnemonic`.
- Tool offset selection (D-code)	`D`, `H` or `tooloffset`.
- Tool selection (T-code)	`T` or `toolselect`.
- Dimension word	`X`, `Y`, `Z`, `U`, `V`, `W`, `P`, `Q`, `R`, `A`, `B` or `C`.
- Interpolation word	`I`, `J`, or `K`.
- functions	`st`, `tf`, `rad`, etc

There are too many types of block bodies for all of them to be listed here.  If a particular block body is sought, reference should be made to the relevant section in the body of this manual.

**Additional information:**
1. A strict set of rules is defined to determine if the block is syntactically valid and if so, in what order the commands within the standard block should be decoded and executed.  
2. Commands and words that may be legally included within a single block are executed independently of the order in which they were programmed.

**Example:**

```
G1 M4 X10 Y10 D2 F1000 S2000 M16
S2000 X10 M4 D2 Y10 M16 G1 F1000.
```

Both these blocks are executed exactly the same even though the order of the commands differ:

#### Block Delimiter/Continuation

The block delimiter signals the end of the block.  There is no special command to be programmed here, as the character generated by the 'Enter' key on the keyboard will be read as the block delimiter.

Block continuation is relevant when a block is longer than one VDU line.  When this occurs, no soft returns will be applied; instead the block will simply run past the end of the screen, out of normal view.  While such blocks are legitimate, they can be split onto two lines to enable easier viewing of the entire block.  This is done by placing the block continuation character (the backslash '\') followed immediately by a newline character (use the enter key) at an appropriate position in the first line, resulting in the remainder of the block being placed on the next line, with no break in the block.  More than one block continuation may be used in a block.

**Additional information:**
1. The line continuation character and following newline character are replaced by a single space character when read by the CNC.
2. A newline must be present at the end of each part program. The AMCore Editor automatically adds this character.
3. The M-code M2 (`stop`) is optional at the end of a program.

### Subroutine Definitions

A subroutine is a series of blocks which can be executed as a group. A subroutine definition consists of:

- A subroutine start line (`sub ...`)
- The blocks that comprise the subroutine
- A subroutine end line (`subend`)

**Additional information:**

1. Subroutines must be defined before they are called.
2. Subroutine definitions are local to a part program. A subprogram may not call a subroutine in a main program or vice versa.

### Comments

Comments can be placed anywhere in a program and are delimited by braces `{ }`. Comment content is ignored by the machine.

**Additional information:**

1. Comments may span any number of lines.
2. Comments may not be nested.

### Case Insensitivity

AMCore EPPL is case insensitive except for string constants. Any combination of upper and lower case letters is accepted in program text.

String constants are case sensitive and are defined as programmed in dual case.

### White Space

White space means spaces and tab characters used to separate words in a part program. White space is generally not required, but is used to aid readability. Tabs are frequently used to distinguish different levels of nesting.

**Additional information:**

1. White space is sometimes needed to terminate an identifier (for example, `linearX20` should be `linear X20`).
2. Use as many white space characters as required.
3. Individual symbols cannot be broken with white space.

## Reserved Words

All built-in names in EPPL are reserved and cannot be used as user-defined variable names, subroutine names, or labels. This includes:

- Flow control keywords (e.g. `if`, `while`, `sub`, `subend`)
- Preparatory word mnemonics (e.g. `rapid`, `linear`, `arccw`)
- Miscellaneous word mnemonics (e.g. `stop`, `spincw`)
- Built-in function names (e.g. `sin`, `cos`, `alarm_trigger`)
- System variable names (e.g. `bv`, `fv`, `iv`, `sv`)
- Built-in constants (e.g. `maxint`, `chord`, `dba_user`)

Attempting to reuse a reserved word as a user identifier results in a syntax error.

### Reserved Prefixes

In addition to the reserved words above, the following identifier prefixes are reserved by the system and must not be used for user-defined variables, subroutines, or labels:

- `pm_` -- reserved for Panel Manager functions and constants (deprecated).
- `tg_` -- reserved for Tool and Cutter Grinder functions and constants.

Using these prefixes for user identifiers may conflict with current or future system names.

## Data Types and Constants

### Boolean

Boolean values represent a 2-state selection (true/false or on/off). 

- `true` is stored as `1`
- `false` is stored as `0`

Boolean constants may be programmed as:

- True: `on`, `true`, or `1`
- False: `off`, `false`, or `0`

### Integer

Integers represent numbers with no fractional part. Integers are stored internally as signed 32-bit values in the range `-2147483647` to `+2147483647`.

Integer constants:

- Decimal (base 10): a sequence of digits (for example `438`)
- Hexadecimal (base 16): `$` followed by hexadecimal digits[^32]

`maxint` is predefined as `2147483647`. Use `-maxint` for the minimum integer value.

### Float

Floats represent numbers with a fractional part. Floats may be represented in decimal or exponential form. Precision is within 15 significant digits with exponential range `10^-307^` to `10^307^`. Floats are stored internally as double precision 64-bit IEEE standard floating point numbers.

A float constant may be programmed as:

- Digits followed by an exponent[^33] (for example `67E-4`)
- Digits followed by `.` and optional exponent (for example `67.E-4`, `234.`)
- Digits followed by `.`, followed by digits, followed by optional exponent (for example `67.93E-4`, `12.0087`)
- `.` followed by digits and optional exponent (for example `.93E-4`, `.001`)
- `pi` (predefined constant pi = `3.14159265358979328`)

### String

A string is a set of printable characters. Maximum string length is 100 characters. Internally, strings are stored as a NUL-terminated array of signed 8-bit ASCII characters.

String constants:

- Empty string: `""`
- Non-empty string: one or more characters enclosed in double quotes

To represent a double quotation mark within a string, use `""` (two double quotation marks).

## Operators

### Arithmetic Operators

Arithmetic operators:

- Unary `+` (for example `+23`, `+2.3`)
- Unary `-` (for example `-23`, `-2.3`)
- Binary `+` addition (for example `1+2`, `fv1+fv2`)
- Binary `-` subtraction (for example `2-1`, `fv1-fv2`)
- Binary `*` multiplication (for example `iv1*3`, `fv1*fv2`)
- Binary `/` division (for example `iv1/iv2`, `2.3/.01`)

### Comparison Operators

Comparison operators:

- `<` less than
- `>` greater than
- `<=` less than or equal to
- `>=` greater than or equal to
- `=` equality[^34]
- `!=` inequality

### Logical Operators

Logical/bitwise operators:

- Unary `!` logical not (Boolean) / bitwise not (Integer)
- Unary `/` logical not (Boolean) / bitwise not (Integer)
- Binary `*` logical and (Boolean context)
- Binary `&` logical and (Boolean) / bitwise and (Integer)
- Binary `+` logical or (Boolean context)
- Binary `|` logical or (Boolean) / bitwise or (Integer)
- Binary `^` logical exclusive or (Boolean) / bitwise exclusive or (Integer)
- Binary `<<` left shift
- Binary `>>` right shift

Operators with two symbols (for example `>>`) must be programmed without spaces between the symbols.

### String Operators

Defined string operators:

- `+` string concatenation
- `<` string less than
- `>` string greater than
- `<=` string less than or equal to
- `>=` string greater than or equal to
- `=` string equal to
- `!=` string not equal to

No unary operators are defined for strings.

### Operator Precedence

Expressions are evaluated from left to right subject to precedence rules. If two operators are at the same precedence level, the left operator is evaluated first.

Grouping operators `(` and `)` can override precedence[^35].

From highest to lowest precedence[^36]:

1. Grouping `()` and array index `[]`
2. Unary logical/bitwise not: `!`, `/`
3. Unary plus/minus: `+`, `-`
4. `*`, `/`, logical and (`&`, `*` in Boolean context), bitwise and (`&`)
5. `+`, `-`, logical or (`|`, `+` in Boolean context), bitwise or (`|`), logical/bitwise exclusive or (`^`)
6. `<<`, `>>`
7. `<`, `>`, `<=`, `>=`
8. `=`, `!=`

### Mixing of Types

The mixing of data types is allowed and conforms to the following rule:

In a binary expression, the operand with the lower type level is converted to the type with the higher type level by using the type casting rules as specified in Type Casting Rules (on page 157). The expression is then evaluated according to the rules associated with the higher level type.

In order from highest to lowest, the type levels are:

- String
- Float
- Integer
- Boolean

Typecasting to a lower level type occurs when an expression of a high level type is assigned (Type Casting Rules) to a variable of lower level type.  For example:

```
bv1 = sv1 + sv2
```

In this case, the typecast is made just before the value of the expression is assigned to the variable.

## Expressions and Assignment

### Expression Syntax

An expression is a combination of variables, constants, and built-in functions separated by operators and, when evaluated, has a literal value and type.

Examples:

- `47`
- `ilb6`
- `16.22 * fv3`
- `sin(82.0)`
- `bv19 & ilb4`

Expressions may mix data types. See Type Casting Rules below for the conversion rules applied.

### Type Casting Rules

To Boolean:

1. Integer → Boolean: `true` if integer `> 0`, otherwise `false`
2. Float → Boolean: `true` if float `> 0`, otherwise `false`
3. String → Boolean:
	- `false` if string is `""`
	- `false` if string is `"FALSE"`
	- `false` if string is `"OFF"`
	- `true` otherwise

To Integer:

1. Boolean → Integer: `1` if `true`, `0` if `false`
2. Float → Integer: truncation of float; `maxint` if float `> maxint`; `-maxint` if float `< -maxint`
3. String → Integer: if valid integer text, convert; otherwise `0`

To Float:

1. Boolean → Float: `1.0` if `true`, `0.0` if `false`
2. Integer → Float: float value equal to integer
3. String → Float: if valid float text, convert; otherwise `0`

To String:

1. Boolean → String: `"TRUE"` or `"FALSE"`
2. Integer → String: decimal character representation
3. Float → String: floating point character representation using `%g` conversion

### Variable Assignment

Synopsys:

`variable = expression`

In variable assignment, an expression is assigned to a variable using `=`.

If the evaluated expression type differs from the target variable type, implicit type conversion is performed to the variable type.

If the target is an uninitialised local variable, it is allocated the type of the expression on the right-hand side.

Multiple assignments per block are allowed:

`variable1 = expr1 variable2 = expr2`

Multiple assignments follow the same rules as normal assignment and expressions may be as complex as required.
